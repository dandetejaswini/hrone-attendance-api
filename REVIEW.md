## Non-Defects Investigated

During code audit and review, several aspects of the system were examined and verified to be **correct as designed**, rather than defects:

1. **Naive BSON Datetimes Returned by PyMongo:**
   - *Investigation:* Even with `MongoClient(tz_aware=True)`, certain PyMongo query paths or mock environments can yield naive UTC datetimes.
   - *Decision:* Not an application defect. The helper `ensure_utc(dt)` explicitly handles this by attaching `timezone.utc` if `dt.tzinfo is None`, guaranteeing all subsequent timestamp arithmetic remains timezone-aware.

2. **Half-Day Status vs. Absent on Short Work Hours:**
   - *Investigation:* Under R4, if an employee logs punch-out with `work_hours < 4.0`, their status is set to `ABSENT` and `half_day = False`. Only work hours in `[4.0, 8.0)` produce `half_day = True`.
   - *Decision:* Not a defect. This accurately reflects standard HR policy and the contract's explicit requirement that fewer than 4 hours constitutes an absence rather than half-day attendance.

3. **Analytics Consuming Stored Derived Fields Instead of Recalculating:**
   - *Investigation:* The analytics endpoints directly aggregate stored fields (`late_minutes`, `work_hours`, `status`, `half_day`) rather than re-computing them from raw punch timestamps.
   - *Decision:* Intentional and required by contract. When attendance records undergo manual regularization via `PATCH /attendance/{emp_code}/{date}`, managers or HR may legitimately adjust status (e.g. `ON_DUTY`) or waive late minutes. If analytics recalculated values dynamically from raw punch times, approved audit adjustments would be erased from reporting.

4. **Competition Ranking (1224) Returning More Items than `limit` on Ties:**
   - *Investigation:* `GET /analytics/leaderboard/late?limit=2` returns 3 items when employees at positions 2 and 3 share identical `total_late_minutes` and `late_count`.
   - *Decision:* Not a defect. Standard competition ranking assigns tied ranks (e.g., 1, 2, 2). The contract specifies filtering by `rank <= limit`. Arbitrarily dropping a tied candidate at the cutoff boundary would violate competition ranking rules.
